# Upgrading to v1.4.0

v1.4.0 records when anything in a project last changed, lists projects by it, and stores a logo and a background for each project.

## Do I need to act?

**Required** only for a client that relies on `GET /v1/projects` listing projects by creation: it now lists the most recently edited first. The other changes add fields and routes, so a client that ignores them keeps working. The release's migrations job updates the database, with nothing to run by hand.

## Sort by creation yourself, if you need it

`GET /v1/projects` orders projects by `editedAt`, newest first. Any write to a project moves it to the front: its fields, beats, scenes, layers, cells, recaps and pictures, moves and deletes included. A client that wants creation order sorts by `createdAt` itself. An owner holds 100 projects at most, so one page of 100 lists them all:

```diff
 const page = await projectList(api, accessToken, { limit: 100 });
-const projects = page.projects;
+const projects = page.projects.toSorted((a, b) => b.createdAt.getTime() - a.createdAt.getTime());
```

## Show when a project last changed

Every project read carries `editedAt`, a `Date` in the JS client. `updatedAt` keeps its meaning: when the project's own title, premise or language last changed.

## Set a logo and a background

`PUT /v1/project/picture?projectID=<id>&picture=logo|background` stores a still WebP or a JPEG, which the service decodes whole before it keeps it. `projectPictureUpdate` sends it from the JS client, and `PROJECT_PICTURE_RULES` holds what each picture accepts:

| Picture      | Shape        | Width         | Size        |
| ------------ | ------------ | ------------- | ----------- |
| `logo`       | square       | 1 to 512 px   | 256 KiB max |
| `background` | exactly 16:9 | 16 to 1280 px | 512 KiB max |

A refused picture answers 422 with its rule in the problem's `reason` tag (`PictureRefusal`: `format`, `ratio` or `dimensions`), and one past its size answers 400. `GET` on the same route serves the bytes to the project's owner, and `DELETE` removes the picture. Pictures stay out of the project's 16 MiB budget.

A project read carries `logoVersion` and `backgroundVersion` while it holds each picture. Put the version in the picture's URL, so a cache keeps each version for good, and keep it as the string the service sends: a `Date` would drop its microseconds.
